# [Python3] 排序后数圈：BFS / 并查集｜我以为要 DP，结果在查户口

**先说做法：按 `(数位和, 数值)` 排序，找出每个数字的目标位置，再统计位置关系形成的环。每个环有 `k` 个位置，就贡献 `k - 1` 次交换。**

先给出 BFS 完整代码：使用“队列 + 入队时标记 + 遍历邻居”的标准模板，总时间 `O(n log n)`，额外空间 `O(n)`。后面再讲为什么数圈能算出最少交换次数，以及并查集怎么做。

## 1. 先上代码：Solution 1，标准 BFS 模板

```python
from collections import deque
from typing import List


class Solution:
    def minSwaps(self, nums: List[int]) -> int:
        def calc_dig_sum(num: int) -> int:
            return sum(int(digit) for digit in str(num))

        ordered_nums = sorted(nums, key=lambda num: (calc_dig_sum(num), num))
        target_index = {num: i for i, num in enumerate(ordered_nums)}
        # graph[i] 存放位置 i 能直接走到的邻居，本题只有一个。
        graph = [[target_index[num]] for num in nums]

        n = len(nums)
        visited = [False] * n

        def bfs(start: int) -> int:
            queue = deque([start])
            visited[start] = True  # 入队时签到，避免重复入队。
            count = 0

            while queue:
                current = queue.popleft()
                count += 1

                for neighbor in graph[current]:
                    if visited[neighbor]:
                        continue
                    visited[neighbor] = True
                    queue.append(neighbor)

            return count

        ans = 0
        for start in range(n):
            if not visited[start]:
                cycle_size = bfs(start)
                ans += cycle_size - 1

        return ans

SolutionBFS = Solution
```

## 2. 排序我会了，然后呢？然后我卡住了

我一开始的思路非常朴素：先排序。

排完之后，目标数组确实有了，交换次数还是没有。

属于是导航已经打开了，车还在停车场。

这道题的数位和只负责告诉我们“最后应该排成什么样”。确定了目标顺序，接下来要解决的是：**每个数字现在住哪儿，应该搬去哪儿？**

拿 `[20, 3, 1]` 举个例子：

```text
位置编号：  0   1   2
现在顺序： 20   3   1
目标顺序：  1  20   3
```

别盯着数值发呆了，给它们登记一下搬家地址：

| 当前位置 | 这里的数字 | 它应该搬去的位置 |
| --- | --- | --- |
| 0 | 20 | 1 |
| 1 | 3 | 2 |
| 2 | 1 | 0 |

所以可以用 `to = [1, 2, 0]` 表示这张表，`to[i]` 表示**位置 `i` 上的数字想去哪儿**。代码为了套用标准 BFS 模板，把每个下一站装进邻居列表，写成 `graph = [[1], [2], [0]]`。

沿着地址走一遍：

```text
0 → 1 → 2 → 0
```

好家伙，问了一圈路，又回来了。这种首尾相接的关系，就叫一个环。

题目说所有数字互不相同，所以每个数字的目标位置唯一，每个位置也只接收一个数字。因此这些位置一定分成若干个互不重叠的环。已经归位的数字，就是自己指向自己的小环。

## 3. 为什么一圈只要 `k - 1` 次？最后一位搭便车

实际换两下就看明白了：

```text
20  3  1
↓ 交换位置 0、2，让 1 回家
 1  3 20
↓ 交换位置 1、2，让 20 回家
 1 20  3
```

三个数字，两次交换。

最后的 `3` 并没有专门安排一次搬家，它在别人归位时跟着回去了。别人搬家它蹭车，主打一个不额外花钱。

一般来说，一个长度为 `k` 的环，每次可以把一个数字交换回正确位置，同时让剩下的位置继续形成一个环。处理到最后两个位置时，交换一下就全部归位。所以需要 `k - 1` 次。

但这只是说明“这么多次能完成”，还得证明“不能更少”。

把数组看成位置之间的排列关系：一次交换，如果发生在同一环里，会把一个环拆成两个；如果发生在不同环之间，会把两个环合成一个。**因此，一次交换最多让环数增加 1。**

设最初有 `c` 个环，最终每个位置都归位，变成 `n` 个单点环。至少需要 `n - c` 次交换。分别把每个环用 `k - 1` 次处理完，恰好达到这个下界。

所以两种计算方式等价：

```text
每一圈的“位置数减一”加起来
              =
       总位置数 - 总圈数
```

不是看着公式眼熟就拿来用了，这回有搬家过程，也有最少次数的证明。

## 4. BFS 标准模板：队列叫号，入队先签到

把队列想成窗口前的队伍：先来先处理。把 `visited` 想成签到表：已经登记的人不能重复排队。

模板按五步走：

1. 起点入队，同时签到。
2. 队列不空，就从队头拿出一个位置。
3. 用 `for neighbor in graph[current]` 遍历它的所有邻居。
4. 邻居已经签到就跳过；没签到就先签到，再加入队尾。
5. 队列空了，这次 BFS 结束。

`graph[current]` 是邻居列表，也就是“从这里能直接走到哪些位置”。本题每个位置只有一个下一站，所以每次遍历邻居时只检查一个位置，但队列和访问标记仍按标准模板写。

比如 `graph = [[1], [2], [0]]`：

| 处理过程 | 队列里还排着谁 | 已处理位置数 |
| --- | --- | --- |
| 起点 0 签到并入队 | `[0]` | 0 |
| 处理 0，让邻居 1 签到并入队 | `[1]` | 1 |
| 处理 1，让邻居 2 签到并入队 | `[2]` | 2 |
| 处理 2，发现邻居 0 已签到，跳过 | `[]` | 3 |

队列空了，一圈数完，`bfs(start)` 返回 `3`，答案加 `3 - 1 = 2`。外层循环继续找还没签到的位置，处理下一圈。

`visited` 不需要走完后改回去。数完又取消签到，下一轮还能再数一次，属于自己给自己刷虚假业绩。

**这里不按 BFS 层数计算交换次数。** 队列只是清点位置的工具，`count` 记录这一圈有几个位置。窗口叫号三次，不代表搬家费要收三次。

标准 BFS 可以只做遍历；需要按层处理或求最短距离时，再增加分层或距离记录。本题按前面的环性质计算答案，不需要额外加上 `for _ in range(len(queue))`。

设最大数位数为 `d`，数位和计算和排序共 `O(nd + n log n)`，BFS 处理全部位置用时 `O(n)`。本题 `d ≤ 10`，总时间记作 `O(n log n)`，额外空间 `O(n)`。每个位置在入队时就标记，因此只会入队一次。

### 坑一：看到“最少”，脑子先喊 BFS

这反应不算错。把整个数组当一个状态，把一次交换当一条边，BFS 确实可以找到最少交换次数。

问题是有 `n!` 种排列，每个状态还能枚举一大堆交换。`n` 最大是十万，电脑还没开始搬家，光给房屋登记就能登记到退休。

本文的 BFS 用的是**位置编号**作为节点，每个位置只有一个下一站，总共只遍历 `n` 个位置。

### 坑二：先给代码起名 DP，以为名字能帮忙转移

我最初那份草稿写着 `Solution 1. DP`，里面完成了排序，答案还安静地待在初始值 `0`。

如果只记录“处理到了第几个位置”，是不够的：剩下的数字在哪里，会直接影响还要交换多少次。如果把整个排列也放进状态，又回到了状态数量太多的问题。

## 6. Solution 2：并查集，我不走了，我直接给你们分组

刚开始看到“并查集”三个字，我的理解大概是：字我都认识，连起来需要重新加载。

先别管术语，把它理解成**一本分组登记册**：

- `find(x)`：查一下，`x` 这一组的代表是谁？
- `union(a, b)`：把 `a` 和 `b` 所在的两组合成一组。
- 两个人查出来的代表相同，就说明本来已经是同一组。

对于 `0 → 1 → 2 → 0`：

```text
刚开始：       {0} {1} {2}    3 组
合并 0 和 1：  {0, 1} {2}     2 组
合并 1 和 2：  {0, 1, 2}      1 组
合并 2 和 0：  {0, 1, 2}      还是 1 组
```

最后一步发现本来就是同组，登记员摆摆手：你们已经是一家人了，别重复占号。

### 先放通用模板，原样留着以后复用

```python
class UnionFind:
    def __init__(self, n: int):
        self.parent = list(range(n))
        self.size = [1] * n
        self.components = n

    def find(self, x: int) -> int:
        while self.parent[x] != x:
            # 路径折半：让当前节点直接指向祖父节点。
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a: int, b: int) -> bool:
        root_a, root_b = self.find(a), self.find(b)
        if root_a == root_b:
            return False

        # 小集合挂到大集合的根节点下。
        if self.size[root_a] < self.size[root_b]:
            root_a, root_b = root_b, root_a
        self.parent[root_b] = root_a
        self.size[root_a] += self.size[root_b]
        self.components -= 1
        return True

```

这里几个变量，可以这样理解：

| 模板里的名字 | 大白话 |
| --- | --- |
| `parent` | 找组代表时，下一步该去找谁 |
| `size` | 这一组有多少人，只看代表位置上的记录 |
| `components` | 现在还剩几组 |
| 路径压缩 | 记下找代表的捷径，下次少跑几趟 |
| 按大小合并 | 让小组跟着大组，避免找代表的路线越接越长 |

`parent` 是并查集内部的登记关系，和“数字应该去哪个位置”的 `to` 不是同一个东西。一个管找组代表，一个管搬家地址，别把物业电话当收货地址填了。

### 再把模板套到本题

```python
from typing import List


class Solution:
    def minSwaps(self, nums: List[int]) -> int:
        def digit_sum(num: int) -> int:
            total = 0
            while num:
                total += num % 10
                num //= 10
            return total

        ordered_nums = sorted(nums, key=lambda num: (digit_sum(num), num))
        target_index = {num: i for i, num in enumerate(ordered_nums)}

        uf = UnionFind(len(nums))
        for i, num in enumerate(nums):
            uf.union(i, target_index[num])

        return len(nums) - uf.components


# 在力扣提交时，需同时复制上面的 UnionFind 类。


SolutionDSU = Solution

```

关键就是这次合并：`uf.union(i, target_index[num])`，意思是**把数字现在的位置和应该去的位置归为同组**。

全部合并完，每个环恰好成为一个组。假设两组分别有 3 个位置、2 个位置，需要的交换次数就是：

```text
(3 - 1) + (2 - 1) = 5 - 2 = 3
```

所以直接返回 `len(nums) - uf.components`。

并查集只是在登记谁和谁同组，没有真的交换数组。这个公式来自本题的置换环性质，也不是所有并查集题都能照抄 `n - 组数`。

排序与数位和计算需要 `O(nd + n log n)`，并查集合并总计摊还 `O(n α(n))`。`α(n)` 增长极慢，可以理解为这里每次操作的平均成本很低。本题总时间可记为 `O(n log n)`，额外空间 `O(n)`。

### 并查集什么时候值得请出来？

读题时遇到“合并、同一组、是否连通、还剩几组、每组多大”，就可以考虑它：

| 问题类型 | 怎么套 |
| --- | --- |
| 无向图连通性、连通块计数 | 一条边就把两端合组，查询时看代表是否相同 |
| 不断添加连接，再查询能否互通 | 每添加一条边就合并，不用每次重新走完整张图 |
| 账号合并、朋友圈分组 | 根据共享信息合并，再按代表收集成员 |
| 相等和不等约束 | 先合并相等关系，再检查不等双方有没有被分到同组 |
| 无向图冗余边 | 加边前已经同组，说明这条边会成环 |
| Kruskal 最小生成树 | 边按权重排序，只选能把两个不同组接起来的边 |
| 网格里相连的陆地 | 合并相邻陆地；水域不能算进岛屿数量 |

它擅长把小组合成大组，普通模板不支持直接拆组或删除连接，也不记录最短路径，不能直接拿来处理有向可达性。需要比值、差值等额外关系时，还得扩展成带权并查集。

## 7. 两个方法，一起检查一下

下面也是笔记里的原代码，包含三个题目示例、单元素、数位和相同的情况，以及本文反复讲的三位置环。

依次运行前面的 BFS、并查集模板和并查集解法，再运行这段验证。两个类的别名就是为此准备的。

```python
cases = [
    ([37, 100], 1),
    ([22, 14, 33, 7], 0),

for name, solver_class in [
    ('Solution 1: BFS', SolutionBFS),
    ('Solution 2: Union-Find', SolutionDSU),

    solver = solver_class()
    for nums, expected in cases:
        actual = solver.minSwaps(nums)
        assert actual == expected, (name, nums, actual, expected)

```

| 方法 | 实际在做什么 | 时间复杂度（本题） | 额外空间 |
| --- | --- | --- | --- |
| BFS | 按队列和邻接表清点每圈的位置 | `O(n log n)` | `O(n)` |
