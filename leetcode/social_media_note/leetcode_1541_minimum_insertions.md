# 1541. 平衡括号字符串的最少插入次数｜从 1021 深度计数到双右括号贪心（Python）

## 完整解法：按连续的右括号分组

下面保留我的 `left_cnt` 思路，将判断下一个字符的两个条件合并。与修正后的原代码逻辑一致，可直接提交。

```python
class Solution:
    def minInsertions(self, s: str) -> int:
        left_cnt = insert_cnt = i = 0

        while i < len(s):
            if s[i] == "(":
                left_cnt += 1
                i += 1
            else:
                if left_cnt > 0:
                    left_cnt -= 1
                else:
                    insert_cnt += 1  # 补一个左括号

                if i + 1 < len(s) and s[i + 1] == ")":
                    i += 2  # 两个连续右括号组成一组
                else:
                    i += 1
                    insert_cnt += 1  # 补齐这一组的第二个右括号

        return insert_cnt + 2 * left_cnt
```

**简单说明：** `left_cnt` 表示已扫描部分尚未匹配的左括号数。每次把右括号凑成一组 `))`，然后消耗一个左括号；没有左括号就补一个。只有一个右括号时补一个 `)`。最后，每个剩余左括号都补两个右括号。

时间复杂度 **O(n)**，额外空间复杂度 **O(1)**。只计算次数，不需要构造插入后的字符串。

## 1. 从 1021 迁移时，先换掉匹配单位

上一题 1021「删除最外层的括号」处理普通合法括号串：一个 `(` 对应一个 `)`，输入已经合法，任务是删除每个原语的外层括号。

1541 的规则变成：一个 `(` 对应两个**连续**的 `)`，左括号在对应右括号组之前。输入可能不平衡，任务是计算最少插入次数。

| 对比点 | 1021：删除最外层的括号 | 1541：最少插入次数 |
| --- | --- | --- |
| 匹配单位 | 一个 `(` ↔ 一个 `)` | 一个 `(` ↔ 一组连续的 `))` |
| 输入保证 | 已经是合法括号串 | 可能缺左括号、缺右括号 |
| 核心状态 | `depth`：当前未闭合左括号数 | `left_cnt`：当前未匹配左括号数；或 `need`：还欠的右括号数 |
| 遇到左括号 | 判断是否为外层，再 `depth += 1` | 分组法直接 `left_cnt += 1`；`need` 法先处理未完成的右括号组 |
| 遇到右括号 | `depth -= 1`，判断是否保留 | 每组 `))` 才能消耗一个左括号 |
| 状态为 0 | 说明一个原语结束 | 说明当前无待匹配左括号；遇到新右括号组需要补左括号 |
| 扫描结束 | 合法输入保证深度归零 | 可能仍有欠账，必须补齐 |
| 输出与空间 | 返回字符串，Python 结果列表占 O(n) | 返回次数，额外空间 O(1) |

1021 可以记住“左先判断，右先减”，因为它判断的是外层边界。1541 判断的是怎样补齐匹配，不能直接照搬这句口诀。

两个最小例子：

- `()` 在 1021 中合法，删除外层后得到空字符串；在 1541 中还要插入一个 `)`，答案为 1。
- `())` 在 1541 中已经平衡，答案为 0；它不是 1021 保证的普通合法输入，不能拿去当 1021 的有效样例。

## 2. 为什么这类题常统计左括号？

### 统计的是“待匹配量”，不是出现总量

从左向右扫描时，左括号会建立一个等待未来闭合的结构；右括号会尝试关闭最近尚未闭合的结构。过去出现过多少个左括号，并不能说明现在还有多少个没闭合。

比如普通括号串 `()(`，左括号总数是 2，但当前未匹配左括号数只有 1。1021 的 `depth` 就是这种“当前待匹配量”，它同时代表嵌套深度。

只看全串数量也不够。1541 的 `))(` 虽然有一个左括号、两个右括号，却顺序错误，最少仍要插入 3 次：在开头补一个 `(`，在末尾补两个 `)`。

### 计数器是同类括号栈的压缩

如果使用栈，每遇到 `(` 就入栈，遇到合法的关闭单位就出栈。只有一种括号、又不需要知道具体匹配下标时，栈内的元素全部相同，未来判断只关心栈里还剩多少个，所以可以压缩成一个整数。

- 1021：一个 `)` 让栈少一个左括号，计数 `-1`。
- 1541 分组法：一组连续的 `))` 才让栈少一个左括号，计数 `-1`。

注意：1541 分组法在一次循环里就处理完整的 `))`，因此在每次循环开始时，没有“只处理了半组”的状态。两个右括号若分开逐个处理，就需要额外表达“这一组还差一个”的信息。

### 不是所有括号题都必须数左括号

`need` 统计欠下的右括号，也是有效状态。从右往左扫描，也可以围绕待匹配的关闭单位设计状态。关键是让状态足以决定后续操作，而不是固定选哪一种括号。

如果包含 `()`、`[]`、`{}` 多种括号，单个数量不能保存类型和嵌套顺序。比如 `([)]` 的数量看起来能对上，嵌套却错误，这时通常需要栈。如果要返回每对括号的下标，也需要保存更多信息。

## 3. 我的分组解法：遇到右括号就凑齐一组

维护两个状态：

- `left_cnt`：当前尚未匹配的左括号数。
- `insert_cnt`：已经决定必须插入的括号数。

遇到 `(` 时先累计；遇到 `)` 时同时解决两件事：

1. **有没有左括号？** 有就消耗一个；没有就在当前右括号组之前插入一个 `(`。
2. **有没有第二个连续的右括号？** 有就一次跳过两个字符；没有就插入一个 `)`，只跳过当前字符。

在原代码中，先更新左括号数量，再判断第二个右括号。可以把它理解成：先为即将完成的这组右括号分配左括号，然后补齐或读取这一组。

扫描结束后仍有 `left_cnt` 个左括号。因为循环从不留下半组右括号，这些左括号每个都完整地缺两个 `)`，所以最后加 `2 * left_cnt`。

用 `s = "))())("` 推演：

| 本轮读取 | 下标变化 | `left_cnt` 变化 | 本轮插入 | 原因 |
| --- | --- | --- | --- | --- |
| 开头 `))` | 0 → 2 | 0 → 0 | 1 | 没有左括号，补一个 `(` |
| `(` | 2 → 3 | 0 → 1 | 0 | 多一个待匹配左括号 |
| 中间 `))` | 3 → 5 | 1 → 0 | 0 | 使用现有左括号 |
| 末尾 `(` | 5 → 6 | 0 → 1 | 0 | 多一个待匹配左括号 |
| 扫描结束 | — | 剩余 1 | 2 | 在末尾补 `))` |

答案为 `1 + 2 = 3`。

## 4. 我的两个实际踩坑

### 坑一：检查后一个字符，边界收紧了一位

最初写的是：

```python
if i < len(s) - 2:
    if s[i + 1] == ")":
        i += 2
```

这里访问的是 `s[i + 1]`，只需要保证 `i + 1 < len(s)`，也就是 `i < len(s) - 1`。

用 `s = "())"`：长度为 3，在 `i = 1` 时，`s[2]` 明明存在。错误条件却要求 `1 < 1`，因此把本来连续的两个右括号拆开处理。原始代码最终返回 3，正确答案是 0。

修正成：

```python
if i + 1 < len(s) and s[i + 1] == ")":
    i += 2
```

Python 的 `and` 会短路：前面的边界判断不成立，就不会访问 `s[i + 1]`。

### 坑二：读完字符串，忘记结算剩余左括号

最初直接 `return insert_cnt`，遗漏末尾的欠账。

用 `s = "("`：循环只把 `left_cnt` 加到 1，`insert_cnt` 仍然是 0，但答案应该是 2。

因此分组法的返回值必须包括：

```python
return insert_cnt + 2 * left_cnt
```

和 1021 对比：1021 输入已合法，扫描完自然归零；1541 输入不保证平衡，循环结束后必须检查还有多少匹配没有完成。

## 5. 更简洁的另一种状态：还欠多少个右括号

两种方法都是 O(n) 时间、O(1) 额外空间。下面的写法省去下标和向后看一个字符的判断，但没有进一步降低复杂度。

```python
class Solution:
    def minInsertions(self, s: str) -> int:
        need = 0
        insert_cnt = 0

        for ch in s:
            if ch == "(":
                if need % 2 == 1:
                    insert_cnt += 1
                    need -= 1
                need += 2
            else:
                need -= 1
                if need == -1:
                    insert_cnt += 1
                    need = 1

        return insert_cnt + need
```

`need` 表示已处理并修补的前缀，若现在结束，还需要在末尾补多少个 `)`。它不是当前缺少的左括号数，也不是已出现右括号的总数。

### 遇到 `(`：先看旧的一组是否完成

一个新左括号带来两个右括号需求，因此通常 `need += 2`。

如果此时 `need` 为奇数，说明此前已读到某组 `))` 的第一个右括号，还差第二个。现在马上要遇到新的 `(`，不能让它把两个右括号隔开，所以先在这个新左括号之前补一个 `)`：

```python
insert_cnt += 1
need -= 1
```

然后再执行 `need += 2`。

用 `s = "()("`：读完前两个字符 `()` 时 `need = 1`；在第三个字符 `(` 之前先补 `)`，再给新左括号增加需求。最后还缺两个右括号，总插入数是 3。

不能只把普通括号题的 `+1` 改成 `+2`。如果忽略“连续”，`s = "()()))"` 的原始数量恰好满足右括号数是左括号数的两倍，所有前缀的加权余额也都非负，但它仍然不平衡：第一个 `)` 后面紧接着 `(`，拆断了右括号组。正确答案为 3。

### 遇到 `)`：减少需求，必要时补左括号

先 `need -= 1`。

如果变成 `-1`，说明这个右括号没有现有左括号可以匹配，必须在它之前补一个 `(`。新左括号需要两个右括号，当前这个 `)` 已经满足一个，所以还欠一个：

```python
insert_cnt += 1
need = 1
```

用 `s = ")"`：补一个 `(` 后形成 `()`，还要在结尾补一个 `)`，总答案为 2。把 `need` 设成 0 或 2 都会算错。

### 最后补上 `need`

扫描结束后，`need` 已包含所有未完成的右括号需求，直接加到答案里即可。它若是奇数，首先补的是当前半组的第二个 `)`；剩下的右括号成组关闭此前的左括号。

## 6. 两种状态如何对应？

在 `need` 法修补后的前缀中，设尚未完全闭合的左括号数量为 `L`，设 `p` 表示是否已经读了当前右括号组的第一个 `)`：未读为 0，已读为 1。则有：

```text
need = 2 * L - p
```

- `need` 为偶数：没有半组右括号，`p = 0`。
- `need` 为奇数：有半组右括号，`p = 1`。

分组法一次处理完整的 `))`，每轮结束后 `p = 0`，只保存 `left_cnt` 就够了。逐字符法用 `need` 的数值和奇偶性，同时编码“还有多少左括号没闭合”和“有没有半组右括号”。

这说明选状态时真正要问的是：**这个变量有没有保留下一步需要的信息？**

用 `s = ")()("` 检查 `need` 法三个特殊处理：

| 下标 | 字符 | 本轮处理后 `need` | 累计 `insert_cnt` | 操作 |
| --- | --- | --- | --- | --- |
| 0 | `)` | 1 | 1 | 需求减到 -1，补一个 `(` |
| 1 | `(` | 2 | 2 | 旧需求为奇数，先补 `)`，再增加 2 |
| 2 | `)` | 1 | 2 | 消耗一个右括号需求 |
| 3 | `(` | 2 | 3 | 再补齐旧半组，再增加 2 |
| 结束 | — | 2 | 3 | 补上剩余 2 个 `)` |

答案为 `3 + 2 = 5`。

## 7. 为什么贪心能得到最少次数？

分组法每次尽量使用已有字符，只在当前匹配无法完成时插入。

1. **连续的两个右括号优先组成一组。** 这不会花费插入次数。若拆开，每个不完整的组都需要补右括号，还会消耗更多左括号；复用已有连续右括号不会让后续匹配需要更多插入。
2. **右括号后面是左括号或已经到末尾。** 原有字符不能删除、不能重排，因此当前右括号必须有一个插入的邻接右括号才能成为完整的关闭单位。补一个就够了；把它放在当前右括号之后，能立即结束这一组。
3. **右括号组前没有可用左括号。** 后面才出现的左括号不能匹配前面的右括号组，至少要插入一个左括号；插入一个已经足够。
4. **结束后还剩左括号。** 分组法不存在半组，每个剩余左括号都确实缺两个右括号，补 `2 * left_cnt` 次恰好够用。

这些选择可以按从左到右的顺序应用到一个最优补齐方案中，且不会增加其插入次数。于是每一步都能维持存在同样好的补齐方案，最后得到的计数就是最小值。`need` 法只是用不同状态逐字符实现同样的补齐规则。

## 8. 复杂度与复盘清单

两种解法都只扫描输入一次，每轮做常数次操作：

| 解法 | 时间 | 额外空间 | 需要留意 |
| --- | --- | --- | --- |
| 左括号计数 + 右括号分组 | O(n) | O(1) | 下一个字符的边界、每组跳过 1 或 2、最终补 `2 * left_cnt` |
| 右括号需求 `need` | O(n) | O(1) | 奇数需求遇到新 `(`、需求减到 -1、最终补 `need` |

需要检查所有字符才能保证答案，因此线性时间已经是最优量级。未做速度基准测试，不声称哪份 Python 代码实际一定更快。

这次记下的重点：

1. 先定义关闭单位：普通括号是 `)`，1541 是连续的 `))`。
2. 计数器表示当前待匹配量，不能用全串左右括号总数代替。
3. 分组处理可以省掉半组状态；逐字符处理必须保留它。
4. 检查 `s[i + 1]` 时，条件应为 `i + 1 < len(s)`。
5. 输入不保证平衡时，扫描结束一定要结算剩余需求。

建议测试：`"())" → 0`、`"(" → 2`、`"))" → 1`、`")" → 2`、`"()(" → 3`、`"))(" → 3`、`"()()))" → 3`、`"(()))" → 1`、`"))())(" → 3`。
