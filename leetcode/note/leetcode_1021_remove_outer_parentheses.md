# 1021. 删除最外层的括号｜从切片边界的坑，到深度一趟扫描（Python）

这道题最容易卡住的地方，是把“前一个原语的结束位置”当成“下一个原语的内部起点”。我最初用计数器找断点，再切片拼接，思路没问题，但第二段开始多保留了一个左括号。

下面先复盘这个下标问题，再给出不用记录断点的一趟扫描写法。

## 题意：每个原语都要去掉一层

原语是不能继续拆成两个非空合法括号字符串的合法括号串。

例如，`(()())(())` 可以拆成 `(()())` 和 `(())`，分别删除最外层的一对括号后，得到 `()()` 和 `()`，拼接结果是 `()()()`。

`()` 本身也是原语，去掉外层后变成空字符串。因此 `()()` 的答案是 `""`。

题目保证输入只包含 `(`、`)`，且整个字符串合法。

## 解法一：记录原语的结束位置，再切片

遇到左括号，计数器 `cnt` 加一；遇到右括号，`cnt` 减一。当 `cnt` 回到 0 时，一个原语结束，记录当前右括号的下标。

我最初的错误写法是：

```python
return "".join(
    s[break_points[i - 1] + 1:break_points[i]]
    for i in range(1, len(break_points))
)
```

以 `s = "()()"` 为例：

```text
下标：       0  1  2  3
字符：       (  )  (  )
break_points = [0, 1, 3]

第一段：s[1:1] = ""
第二段：s[2:3] = "("   ← 把第二段的外层左括号留下了
```

问题在于：前一个右括号下标是 `prev_close`，下一段的外层左括号就在 `prev_close + 1`。要去掉它，内部起点应当是 `prev_close + 2`。

Python 切片不包含右端点，因此结束位置直接使用当前原语的右括号下标即可。第一段从整个字符串的下标 0 开始，内部起点是 1，需要单独处理：

```python
class Solution:
    def removeOuterParentheses(self, s: str) -> str:
        break_points = [0]
        cnt = 0

        for i, c in enumerate(s):
            if c == "(":
                cnt += 1
            else:
                cnt -= 1
                if cnt == 0:
                    break_points.append(i)

        return "".join(
            s[1:break_points[1]] if i == 1
            else s[break_points[i - 1] + 2:break_points[i]]
            for i in range(1, len(break_points))
        )
```

设字符串长度为 `n`，原语数量为 `k`。扫描、所有切片的总长度和最终拼接都是线性的，所以时间复杂度为 **O(n)**。断点数组占 O(k) 空间；计入切片与结果字符串，空间上界为 **O(n)**。

## 解法二：用深度直接筛选内部括号

无需等到一个原语结束才处理它。扫描每个字符时，可以直接判断它是不是外层括号。

令 `depth` 表示当前还没有闭合的左括号数量，也就是嵌套深度。

- 遇到 `(`：先判断 `depth > 0`，满足时保留，然后把深度加一。
- 遇到 `)`：先把深度减一，再判断 `depth > 0`，满足时保留。

两种括号的判断时机不同，是因为外层左括号出现前，深度是 0；外层右括号处理后，深度才回到 0。

```python
class Solution:
    def removeOuterParentheses(self, s: str) -> str:
        result = []
        depth = 0

        for c in s:
            if c == "(":
                if depth > 0:
                    result.append(c)
                depth += 1
            else:
                depth -= 1
                if depth > 0:
                    result.append(c)

        return "".join(result)
```

用 `(())()` 手动走一遍：

| 下标 | 字符 | 深度变化 | 是否保留 | 当前结果 |
| --- | --- | --- | --- | --- |
| 0 | `(` | 0 → 1 | 否，增加前深度为 0 | `""` |
| 1 | `(` | 1 → 2 | 是，增加前深度大于 0 | `(` |
| 2 | `)` | 2 → 1 | 是，减少后深度大于 0 | `()` |
| 3 | `)` | 1 → 0 | 否，减少后深度为 0 | `()` |
| 4 | `(` | 0 → 1 | 否，增加前深度为 0 | `()` |
| 5 | `)` | 1 → 0 | 否，减少后深度为 0 | `()` |

最终结果是 `()`。

## 正确性说明

在处理每个字符之前，`depth` 等于此前已扫描前缀中尚未匹配的左括号数量。

一个原语的外层左括号出现时，之前的深度必然为 0；原语内部的左括号出现时，深度至少为 1。因此，先判断深度再增加，只会保留内部左括号。

一个原语的外层右括号闭合后，深度必然为 0；原语内部的右括号闭合后，外层仍未闭合，深度至少为 1。因此，先减少深度再判断，只会保留内部右括号。

所有内部字符按原顺序加入结果，恰好得到每个原语删除外层括号后的拼接结果。

## 复杂度与两种写法的差别

第二种解法只扫描一次，最后拼接一次，时间复杂度为 **O(n)**。`depth` 本身占 O(1) 空间，但 Python 的结果列表和返回字符串都需要存储，所以这份实现的空间上界仍是 **O(n)**。

两种解法的时间复杂度相同。第二种省掉了断点和切片步骤，判断更直接；它是否实际更快，取决于 Python 的实现、输入结构和运行环境，不能仅凭“一趟扫描”就认定一定更快。

## 这次记下的三个细节

1. 切片前先写清“存的是右括号下标，还是下一段的起点”，再计算偏移。
2. 深度法要记住判断顺序：左括号先判断，右括号先减少深度。
3. 样例校验应当比较 `ans == expected`。Notebook 原先的 `ans == s` 只是比较结果与输入，不能判断答案是否正确。

```python
s = "(()())(())(()(()))"
expected = "()()()()(())"
ans = Solution().removeOuterParentheses(s)
print(ans == expected)
```
