# 1541 踩坑笔记｜从 1021 迁移时，哪些规则需要改？

详细解法见 [1541 完整题解](./leetcode_1541_minimum_insertions.md)。本页用于快速复盘和查边界。

## 我的两处错误与最小反例

| 错误 | 最小反例 | 原始结果 | 正确结果 | 修正 |
| --- | --- | --- | --- | --- |
| 访问下一位却用 `i < len(s) - 2` | `())` | 3 | 0 | `i + 1 < len(s)` |
| 直接返回已插入次数，漏掉剩余左括号 | `(` | 0 | 2 | 再加 `2 * left_cnt` |

第一处错误把末尾已有的 `))` 拆开处理。第二处错误把“输入读完了”当成“匹配完成了”。

两个问题需要分别检查：边界修正后，单个 `(` 仍然需要末尾结算。

## 与 1021 的迁移对照

| 需要确认的问题 | 1021 | 1541 |
| --- | --- | --- |
| 一个左括号需要什么关闭单位？ | 一个 `)` | 两个连续的 `)` |
| 输入保证平衡吗？ | 保证普通括号合法 | 不保证 |
| 数的是什么？ | 当前未闭合左括号数 `depth` | 当前未匹配左括号数 `left_cnt`；或右括号需求 `need` |
| 一次消耗几个左括号？ | 每个 `)` 消耗一个 | 每组 `))` 消耗一个 |
| 结束后要做什么？ | 合法输入的深度自然归零 | 结算剩余需求 |
| 结果是否需要存储？ | 要构造字符串，列表空间 O(n) | 只统计次数，额外空间 O(1) |

1021 的“左先判断，右先减”用于判断外层括号；1541 的关键是补齐匹配。题目相似，不代表分支含义相同。

## 为什么统计左括号数量？

从左到右，左括号建立等待闭合的结构，右括号关闭结构。只有一种括号、又不需要匹配位置时，栈里的元素相同，记录栈的长度就够了。

因此核心是**当前未匹配数量**，不是左括号总数。普通括号串 `()(` 出现过两个左括号，但尚未匹配的只有一个。

1541 中，分组法在每轮结束前读完或补齐整组 `))`，因此不会留下半组状态。逐字符法则用 `need` 的奇偶性保存半组信息。

并非所有题都只能统计左括号：也可以统计右括号需求 `need`。多种括号、或者要返回匹配下标时，就需要保存类型、顺序或位置。

## need 写法的三个易错点

| 分支 | 含义 | 正确操作 | 验证例子 |
| --- | --- | --- | --- |
| `need` 为奇数，又遇到 `(` | 旧右括号组只完成一半 | 先补 `)`，需求减一，再为新 `(` 加二 | `()(` → 3 |
| 读到 `)` 后，`need == -1` | 缺少能匹配当前 `)` 的左括号 | 补 `(`，当前 `)` 已满足一半，设 `need = 1` | `)` → 2 |
| 扫描结束 | 前缀仍有未完成需求 | 答案加 `need` | `(` → 2 |

如果 `L` 是修补后的前缀中未完全闭合的左括号数，`p` 表示是否已经读过半组右括号，则 `need = 2 * L - p`。这就是奇偶性能表达半组的原因。

## 不能忽略的两个条件

1. **顺序：** `))(` 左 1 右 2，数量比例正确，但至少补 3 次。后来的左括号不能匹配先前的右括号。
2. **连续：** `()()))` 左 2 右 4，数量比例正确，所有前缀的加权余额也非负，却仍要补 3 次。第一个右括号后立即遇到左括号，打断了 `))`。

因此，单纯计算 `2 * 左括号总数 - 右括号总数` 不能解决本题。

## 最小测试集与本次验证

```text
())     → 0   已经平衡，检查向后看一位的边界
(       → 2   剩余左括号结算
)       → 2   缺左括号，也缺第二个右括号
))      → 1   完整右括号组，缺左括号
()(     → 3   半组后遇到新左括号
))(     → 3   总数满足比例，顺序不满足
()()))  → 3   总数满足比例，连续性不满足
)()(    → 5   负需求、半组和末尾结算全部覆盖
```

本次验证原修正版、等价紧凑分组版和 `need` 版：与独立 Dijkstra 插入/消费字符状态图比对，长度 1—9 的全部 1022 个括号串均通过；另验证 100 个固定随机种子用例及 3 个大规模边界用例。Notebook 的两种解法各通过 13 个样例。没有实际提交力扣在线评测，没有测量运行速度。
